detectgraph()

Lifecycle Function
Hardware Detection

The detectgraph() function in graphics.h is used to detect the system's graphics hardware capabilities without initializing the graphics mode. It works alongside initgraph() to determine the best available BGI driver and mode for your Turbo C graphics programs, supporting VGA, EGA, and other legacy graphics standards.

Description

The detectgraph() function detects the system's graphics hardware and determines the best available graphics driver and mode. Unlike using DETECT with initgraph(), this function only checks the hardware without actually initializing the graphics system.

This function is useful when you want to query the system's BGI graphics capabilities before committing to a specific graphics mode in your DOS graphics programs. It allows you to make informed decisions about which driver and mode to use, or to display information about available graphics capabilities to the user.

Syntax

C 
void detectgraph(int *graphdriver, int *graphmode);

Parameters

  • graphdriver
    Pointer to an integer that receives the detected graphics driver constant. Common values include CGA, EGA, VGA, etc. If no graphics hardware is detected, this will be set to -2 (grNotDetected).
  • graphmode
    Pointer to an integer that receives the recommended graphics mode for the detected driver. This represents the highest resolution mode available for the detected driver.

Return Value

This function does not return a value. The results are stored in the variables pointed to by the parameters.

How It Works

The detection process follows this priority order:

  1. 1. VGA Detection
    First checks for VGA or higher (SVGA) adapters. If found, sets driver to VGA and mode to VGAHI (640x480).
  2. 2. EGA Detection
    If no VGA, checks for EGA adapter. Sets driver to EGA and mode to EGAHI (640x350).
  3. 3. CGA Detection
    If no EGA, checks for CGA. Sets driver to CGA and mode to CGAHI (640x200).
  4. 4. No Graphics
    If no graphics adapter is detected, sets graphdriver to grNotDetected (-2).

Example Implementation

C 
#include 
#include 
#include 

int main() {
    int gd, gm;
    
    // Detect graphics hardware without initializing
    detectgraph(&gd, &gm);
    
    // Check if graphics hardware was detected
    if (gd == -2) {  // grNotDetected
        printf("No graphics hardware detected!\n");
        return 1;
    }
    
    // Display detected information
    printf("Detected Graphics Driver: %d\n", gd);
    printf("Recommended Mode: %d\n", gm);
    
    // Now initialize with the detected values
    initgraph(&gd, &gm, "");
    
    if (graphresult() != grOk) {
        printf("Graphics initialization failed!\n");
        return 1;
    }
    
    // Display driver name
    setcolor(WHITE);
    outtextxy(10, 10, "Graphics system initialized!");
    
    char driverInfo[100];
    sprintf(driverInfo, "Driver: %s", getdrivername());
    outtextxy(10, 30, driverInfo);
    
    getch();
    closegraph();
    return 0;
}

Using Detection Results

You can use the detected values directly with initgraph(), or modify them before initialization:

C 
int gd, gm;
detectgraph(&gd, &gm);

// Use detected values as-is
initgraph(&gd, &gm, "");

// OR modify the mode to a lower resolution
if (gd == VGA) {
    gm = VGAMED;  // Use 640x350 instead of 640x480
}
initgraph(&gd, &gm, "");

Comparison: detectgraph() vs DETECT

Both methods achieve similar results, but have different use cases:

C 
// Method 1: Using DETECT with initgraph()
// (Automatic detection during initialization)
int gd = DETECT, gm;
initgraph(&gd, &gm, "");
// gd and gm are set to detected values after initgraph()

// Method 2: Using detectgraph()
// (Detection without initialization)
int gd, gm;
detectgraph(&gd, &gm);
// Check detected values before initializing
if (gd != grNotDetected) {
    initgraph(&gd, &gm, "");
}

grNotDetected -2 N/A

Best Practice: Always check if detectgraph() returns a valid driver before attempting to initialize graphics. This prevents crashes on systems without graphics hardware or when running in text-only environments.

Note: In most modern emulated environments (including this online compiler), detectgraph() will return VGA as the detected driver since VGA support is standard in emulators.

Frequently Asked Questions

What's the difference between detectgraph() and using DETECT with initgraph()?

detectgraph() only queries the graphics hardware and returns information about available drivers and modes without actually initializing graphics. Using DETECT with initgraph() both detects the hardware AND initializes the graphics system in one step. Use detectgraph() when you want to check capabilities before committing to initialization.

What graphics drivers can detectgraph() identify?

detectgraph() can identify various BGI graphics drivers including CGA, EGA, VGA, SVGA, and others. In modern environments, it typically returns VGA (driver code 9) as the best available option. The function stores the driver code in the graphdriver parameter and the recommended mode in graphmode.

What value indicates no graphics hardware was detected?

If no graphics hardware is detected, detectgraph() sets the graphdriver parameter to grNotDetected, which has a value of -2. You should always check for this value before attempting to initialize graphics to prevent program crashes.

Can I use detectgraph() results with initgraph()?

Yes, the values returned by detectgraph() in the graphdriver and graphmode parameters can be directly passed to initgraph(). This allows you to detect the best graphics mode and then initialize with those exact settings for optimal compatibility.

Does detectgraph() work the same in emulators as on real DOS systems?

In most emulators and online compilers, detectgraph() typically returns VGA as the detected driver since VGA support is standard. On real vintage DOS systems, it would return the actual hardware capabilities of the installed graphics card, which could be CGA, EGA, or VGA depending on the system.
