closegraph()

Lifecycle Function
Cleanup

The closegraph() function in graphics.h is used to properly shutdown the BGI graphics system and return to text mode. It works with initgraph() to manage the graphics lifecycle in Turbo C and DOS environments, releasing memory and video resources allocated during graphics initialization.

Description

The closegraph() function shuts down the graphics system and releases all resources allocated by initgraph(). It restores the video mode to the original text mode before the graphics system was initialized, effectively returning the display to the standard console/terminal state.

This function should be called at the end of every graphics.h program to ensure proper cleanup of memory, video buffers, and BGI graphics drivers. Failure to call closegraph() may result in memory leaks or the display remaining in graphics mode, requiring a system reset in DOS environments.

Syntax

C 
void closegraph(void);

Parameters

This function takes no parameters.

Return Value

This function does not return a value.

What closegraph() Does

  • Restores Text Mode
    Switches the display back from graphics mode to the original text/console mode.
  • Frees Memory
    Deallocates memory used for graphics buffers, fonts, and internal data structures.
  • Unloads Drivers
    Releases the BGI driver files that were loaded by initgraph().
  • Resets Palette
    Restores the default system color palette.

Example Implementation

C 
#include 
#include 

int main() {
    int gd = DETECT, gm;
    
    // Initialize graphics mode
    initgraph(&gd, &gm, "");
    
    // Check for errors
    if (graphresult() != grOk) {
        printf("Graphics initialization failed!\n");
        return 1;
    }
    
    // Draw some graphics
    setcolor(YELLOW);
    setfillstyle(SOLID_FILL, RED);
    bar3d(100, 100, 300, 200, 20, 1);
    
    setcolor(WHITE);
    outtextxy(150, 250, "Press any key to exit...");
    
    // Wait for user input
    getch();
    
    // Clean up and restore text mode
    closegraph();
    
    return 0;
}

Common Patterns

Standard Pattern: Always pair initgraph() with closegraph():

C 
int main() {
    int gd = DETECT, gm;
    initgraph(&gd, &gm, "");  // Initialize
    
    // ... your graphics code ...
    
    getch();                   // Wait before closing
    closegraph();              // Clean up
    return 0;
}

Error Handling Pattern: Ensure closegraph() is called even if errors occur:

C 
int main() {
    int gd = DETECT, gm;
    initgraph(&gd, &gm, "");
    
    int result = graphresult();
    if (result != grOk) {
        printf("Error: %s\n", grapherrormsg(result));
        closegraph();  // Still clean up!
        return 1;
    }
    
    // Draw graphics
    circle(320, 240, 100);
    
    getch();
    closegraph();
    return 0;
}

Related Functions

Functions that work with closegraph():

  • initgraph()
    The counterpart to closegraph() - initializes the graphics system. Always call initgraph() before closegraph().
  • graphresult()
    Returns the error code from the last graphics operation. Useful for checking if closegraph() needs to be called.
  • restorecrtmode()
    Similar to closegraph() but preserves the graphics data in memory. Use closegraph() for complete cleanup.

Best Practice: Always call getch() before closegraph() to prevent the graphics window from closing immediately, allowing the user to see the final output.

Warning: Calling closegraph() without a prior successful initgraph() call may produce unpredictable results. Always check that graphics initialization succeeded before attempting to close it.

Frequently Asked Questions

What happens if I don't call closegraph() in my program?

If you don't call closegraph(), the graphics mode remains active and the system stays in graphics mode. In DOS environments, this can leave the screen in an unusable state, requiring a system reset. The program may also leak memory since graphics resources aren't properly freed.

What's the difference between closegraph() and restorecrtmode()?

closegraph() performs a complete cleanup - it restores text mode AND frees all graphics resources including memory, buffers, and drivers. restorecrtmode() only switches the display back to text mode without freeing resources, allowing you to temporarily exit graphics mode and later return to it.

Can I call closegraph() without calling initgraph() first?

Calling closegraph() without a successful initgraph() call may produce unpredictable results or errors. Always ensure initgraph() was called and returned successfully before calling closegraph(). You can check graphresult() to verify initialization status.

Does closegraph() return any value?

No, closegraph() has a return type of void and does not return any value. If you need to check for errors during graphics operations, use the graphresult() function before calling closegraph().

Why should I call getch() before closegraph()?

Calling getch() before closegraph() pauses the program and waits for a keypress, allowing the user to see the final graphics output. Without this pause, the graphics window closes immediately when closegraph() is called, making it impossible to see the results of your drawing operations.
