Compiler Documentation

A comprehensive guide to the Online graphics.h Compiler.

Overview

The Online graphics.h Compiler is a browser-based development environment that lets you write, compile, and execute graphics.h C/C++ programs without any local installation. It emulates a full Turbo C++ 3.0 environment using WebAssembly-powered DOS emulation, so the entire compilation and execution pipeline runs client-side inside your browser.

Key Fact: There is no backend compilation server. Your code never leaves your browser. Everything -- from the text editor to the Turbo C++ compiler to the DOS graphics renderer -- runs 100% locally within the page.

Architecture

The compiler page is split into two main panels: the Ace Code Editor on the left and the DOS Canvas (powered by JS-DOS) on the right. These are orchestrated by compiler.js, which manages script loading, caching, compilation, keyboard focus, theme toggling, and error detection.

The Interface

Header Bar

The header bar contains all the primary controls, arranged left-to-right:

  • Home Button: Navigates back to the landing page (index.html).
  • Logo: "Online graphics.h Compiler" -- centered. On mobile, it shortens to "graphics.h Compiler".
  • Theme Toggle: Switches between Dark (Monokai) and Light (Textmate) themes. Saved to localStorage.
  • Demo Selector: A dropdown labeled "Demo:" with four pre-loaded example programs. Selecting a demo replaces the editor content. Re-selecting the same demo forces a fresh reload from the server.
  • Save Indicator: Shows "Saved" (green) or "Not Saved" (default). Updates in real-time as you type.
  • Save Button: Manually saves the current code to localStorage under the key tc_code.
  • Compile and Run Button: The primary action button. Initiates the full compilation and execution pipeline described below.

Code Editor (Left Panel)

The editor is powered by Ace Editor with C++ language mode. It includes:

  • Syntax Highlighting: C/C++ keywords, strings, comments, preprocessor directives are color-coded.
  • Autocompletion: Triggered by typing or Ctrl+Space. Requires the ext-language_tools extension.
  • Line Numbers: Visible gutter on the left with active line highlighting.
  • Code Wrapping: Long lines wrap to fit the visible area.
  • Editor Footer: Displays a live count of lines and characters in the current file.
  • Fullscreen Toggle: Expands the editor to fill the entire screen, hiding the DOS output panel. Toggle it again to return.
  • Clear Button: Clears the entire editor content after a confirmation dialog.

DOS Output (Right Panel)

The right panel contains an HTML <canvas> element where DOSBox renders its output. This is where you see the Turbo C++ compilation process, text output, and graphical output from graphics.h programs.

  • Click to Interact: After compilation, a blocker overlay appears prompting you to click the canvas. This transfers keyboard focus from the editor to the DOS terminal so your key presses go to the running program.
  • Escape to Return: Press Escape at any time to return keyboard focus to the code editor.
  • Pixel-Perfect Rendering: The canvas uses image-rendering: pixelated to preserve the sharp pixel-art look of DOS graphics.
  • Aspect Ratio: In fullscreen mode, object-fit: contain ensures the canvas scales proportionally without stretching.

Compilation Error Panel

If the Turbo C++ compiler detects errors, a panel slides up from the bottom of the DOS output area with the full error text from ERR.TXT. The panel polls the virtual filesystem every 1 second after a run starts.

  • Copy Errors: Copies the error text to your clipboard.
  • Expand/Collapse: Toggles the panel between 50% and 100% height.
  • Close: Dismisses the error panel entirely.

Compilation Workflow

When you click "Compile and Run", the following sequence happens:

  1. Validation: The editor content is checked. If it's empty, you get an alert.
  2. Cleanup: Any previous DOS instance is terminated. The error panel is hidden and reset.
  3. Initialize DOS: A new JS-DOS instance is created on the canvas. The wdosbox.js WebAssembly module is loaded (CDN first, local fallback).
  4. Load Compiler: The tc-v1.zip file (containing Turbo C++ 3.0) is fetched from cache (IndexedDB) or downloaded from /tc-zip. It is then extracted into the virtual DOS filesystem.
  5. Write Source Code: Your code from the editor is written to /TURBOC3/BIN/USER.CPP inside the virtual filesystem.
  6. Generate Batch Script: An AUTOEXEC.BAT is created to automate the compilation and execution.
  7. Execute: DOSBox boots and runs the batch script automatically.
  8. Monitor Errors: A 1-second interval begins polling /TURBOC3/BIN/ERR.TXT for compilation errors.

The Compile Command

The actual command that compiles your code inside DOS is:

TCC -I..\INCLUDE -L..\LIB -n. USER.CPP ..\LIB\GRAPHICS.LIB > ERR.TXT
Flag Meaning
TCC Turbo C Compiler executable
-I..\INCLUDE Path to header files (graphics.h, conio.h, etc.)
-L..\LIB Path to library files for linking
-n. Output the compiled .EXE to the current directory
USER.CPP Your source code file
..\LIB\GRAPHICS.LIB The BGI graphics library, linked explicitly
> ERR.TXT Redirect compiler output (errors/warnings) to a text file

The AUTOEXEC.BAT Script

This is the full batch file generated and injected into DOSBox on every compile:

@ECHO OFF
CD TURBOC3\BIN
IF EXIST USER.EXE DEL USER.EXE
IF EXIST ERR.TXT DEL ERR.TXT
TCC -I..\INCLUDE -L..\LIB -n. USER.CPP ..\LIB\GRAPHICS.LIB > ERR.TXT
IF EXIST USER.EXE GOTO SUCCESS
CLS
ECHO ========================================
ECHO COMPILATION ERRORS:
ECHO ========================================
TYPE ERR.TXT
ECHO.
PAUSE
EXIT
:SUCCESS
CLS
USER.EXE
PAUSE

It first cleans up any previous build artifacts, then compiles. If USER.EXE is produced, it runs it. Otherwise, it displays the error log.

Features

Demo Programs

Four pre-loaded demo programs are available from the dropdown in the header:

Demo Description
Graphics Demo Basic shapes (circle, rectangle), text output. Good first test.
Circle Pattern Concentric circle pattern using loops.
Bouncing Ball Animated ball with physics simulation using delay() and cleardevice().
Shooter Game A simple interactive shooting game demonstrating keyboard input.

Demo files are cached in localStorage with a 7-day TTL. Selecting the same demo twice triggers a force-reload that bypasses the cache.

Themes

Click the moon/sun icon in the header to toggle between Dark and Light mode. The preference persists across sessions via localStorage. The Ace Editor theme changes in sync: Monokai for dark, Textmate for light.

Saving Code

Your code is saved to localStorage under the key tc_code. You can save manually with the Save button or Ctrl+S. When you revisit the page, if saved code exists, it is automatically restored into the editor. Loading a demo clears the saved code.

Fullscreen Mode

Both the editor and the DOS output panel have a fullscreen toggle button (the expand icon in the panel header). Activating fullscreen on one panel hides the other. Click the button again to exit fullscreen.

Caching System

The compiler uses a two-tier caching strategy to minimize downloads and enable offline support:

  • IndexedDB (GraphicsHCompilerCacheLegacy database): Stores the large tc-v1.zip compiler package (~50MB) as a Blob. Has a 7-day TTL. After the first download, subsequent "Compile and Run" actions load instantly from this cache.
  • localStorage: Stores user code (tc_code key), demo file source code (prefixed demo_cache_legacy_), and theme preference (theme key).

Performance Impact: First run: ~5-15 seconds (downloads compiler). Subsequent runs: ~1-3 seconds (loaded from cache).

Offline Support

Every external dependency (JS-DOS, Ace Editor, themes, language mode) has a CDN primary URL and a local fallback in /compiler-assets/libs/. The script loader tries CDN first with a 5-second timeout. If CDN fails, it automatically loads the local copy. This means the compiler works completely offline after you've loaded the page at least once (provided the TC ZIP is cached in IndexedDB).

Troubleshooting

"Graphics Error: BGI Error"

Ensure your code initializes the graphics driver correctly with initgraph(). The environment is pre-configured with BGI drivers in the standard Turbo C path. Use int gd = DETECT, gm; initgraph(&gd, &gm, ""); with an empty string for the driver path.

Compilation Takes Too Long

The first run after clearing your browser cache requires downloading the ~50MB compiler package. Subsequent runs use the IndexedDB cache and should be fast. Ensure your internet connection is stable for the initial download.

Nothing Happens After Clicking Run

Open the browser DevTools console (F12) and look for error messages prefixed with [Graphics.h Compiler]. Common causes: ad blockers interfering with CDN script loading, IndexedDB disabled in privacy settings, or WebAssembly not supported.

Keyboard Not Working in DOS

Click directly on the DOS canvas to transfer keyboard focus. A "Click to interact" overlay should appear. After clicking, your key presses go to the DOS program. Press Escape to return focus to the editor.

Safari Users: Safari has limited WebAssembly memory (512MB max) and may fail for very large programs. Desktop Chrome or Firefox is recommended for the best experience.
